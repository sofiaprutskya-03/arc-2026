# ARC 2026 — ESP32: технічні нотатки для вибору алгоритмів

> **Статус:** конспект найважливішого з матеріалів, наданих користувачкою (FastAccelStepper README, Keyestudio KS0413, KS5011). Це **не** результати апаратного тестування й не підтвердження сумісності конкретного зібраного робота.

## 1. Мета проєкту

Робот-маніпулятор із клешнею на одноосьовій лінійній платформі. Потрібні: (1) ручне керування джойстиком/кнопками з плавним стартом і зупинкою; (2) напівавтоматичне переміщення вантажу між комірками AB → CD; (3) утримання горизонтального положення клешні; (4) окреме силове живлення приводів та контролера; (5) надійна демонстрація. Джерело: завдання ARC 2026, надане раніше.

## 2. Апаратна основа — Keyestudio KS5011

- **Комплект:** Keyestudio ESP32 Learning Kit Complete Edition, позначка **KS5011** на коробці (не KS5011F).
- Офіційна сторінка: https://wiki.keyestudio.com/KS5011%28KS5011F%29_Keyestudio_ESP32_Learning_Kit_Complete_Edition
- Матеріали/приклади виробника: https://fs.keyestudio.com/KS5011
- Набір — навчальний, із платою ESP32, датчиками, модулями та дротами. Сторінка заявляє 108 навчальних матеріалів, але в наданому переліку наведені проєкти 01–37; не припускати наявності решти без перевірки файлів.

| Проєкт | Назва в документації | Застосування |

## 3. Плата ESP32: відомості з Keyestudio KS0413

- Окрема документація **KS0413 ESP32 Core Board** описує модуль **ESP-WROOM-32**, USB–UART **CP2102-GMR**, плату з входом живлення **5 В**, підтримкою Wi-Fi 2,4 ГГц і Bluetooth 4.2.
- У Arduino IDE документація пропонує **ESP32 Dev Module**, правильний послідовний порт і **Serial Monitor 115200**; для завантаження іноді потрібно утримувати **BOOT**.
- Драйвер CP210x: https://www.silabs.com/developers/usb-to-uart-bridge-vcp-drivers
- **Важливе застереження:** KS0413 — документація окремої плати. Треба звірити маркування саме вашої плати з KS5011, перш ніж переносити її розпінування та електричні параметри.
- **Не плутати:** живлення плати 5 В через передбачений вхід ≠ допустима напруга на GPIO; GPIO ESP32 працюють із логікою 3,3 В. Не підключати силове живлення моторів безпосередньо до GPIO.
- Застарілий спосіб встановлення Arduino IDE 1.8.7 і ручного копіювання ESP32 core із KS0413 не є обов'язковим: обирати актуальну перевірену версію Arduino-ESP32 і фіксувати її у проєкті.

## 4. FastAccelStepper — що реально дає

**Репозиторій:** https://github.com/gin66/FastAccelStepper  
**API:** https://github.com/gin66/FastAccelStepper/blob/master/extras/doc/FastAccelStepper_API.md  
**Приклад:** https://github.com/gin66/FastAccelStepper/blob/master/examples/UsageExample/UsageExample.ino  
**Ліцензія за наданим записом ecosyste.ms:** MIT; актуальний стан перевірити в репозиторії.  
**Джерело метаданих:** ecosyste.ms, знімок із синхронізацією у травні 2025 року — статистика може бути застарілою.

### Призначення й головне обмеження

- Бібліотека керує кроковими двигунами **через драйвери імпульсного типу STEP/DIR** (наприклад A4988); має необов'язковий сигнал ENABLE.
- Для **28BYJ-48 + ULN2003**, що зазвичай керується чотирма фазними входами, **не є прямою заміною** AccelStepper. Потрібно встановити реальну модель двигуна/драйвера.
- Підтримує класичний ESP32, але сумісність залежить від версій Arduino core / ESP-IDF. У наданому README прямо зазначено, що Arduino core 3.0.x з ESP-IDF 5.0–5.1 не компілюється; для ESP-IDF ≥5.3 описана реалізація на RMT. Перевіряти **конкретну версію** бібліотеки, core і результати компіляції, а не покладатися на старий README.

### Корисні можливості

- `moveTo(position)` — абсолютна ціль у кроках; `move(delta)` — відносне переміщення.
- Налаштування швидкості (`setSpeedInHz`) і прискорення (`setAcceleration`), плавний розгін/гальмування.
- Неблокувальна робота через апаратні механізми/задачі: не потрібно постійно викликати функцію генерації кроків у `loop()`.
- `setDirectionPin`, `setEnablePin`, `setAutoEnable` — конфігурація драйвера; затримки ввімкнення/вимкнення та зміни напрямку.
- `stopMove()` для штатної зупинки руху; окремо перевірити API аварійної зупинки й поведінку на конкретній версії.
- Черги команд та майже синхронний старт кількох двигунів на низькому рівні.
- У README заявлено до **200 000 кроків/с** для ESP32 і до 14 моторів у старій конфігурації ESP-IDF 4.x або 8 у ESP-IDF ≥5.3. Це **межі бібліотеки за описом**, а не швидкість/точність вашої механіки.

### Технічні ризики, описані авторами

1. **Перенаправлення цілі під час руху:** команда `moveTo()` в протилежному напрямку може спричинити спочатку гальмування з подальшим розворотом; не припускати миттєвої зупинки.
2. **Лічильник позиції 32-бітний:** при великих значеннях можливе переповнення; у робочому діапазоні задавати фізичні межі.
3. **Відсутність реального зворотного зв'язку:** підраховані кроки не доводять, що двигун фізично не пропустив кроків.
4. **Джерело живлення й земля:** автори описують проблеми з позицією через погане живлення/заземлення.
5. **Мікрокрокування:** вимкнення/увімкнення драйвера може спричиняти стрибок ротора до повного кроку.
6. **Синхронізація кількох осей:** власний розгін кожної осі не гарантує узгодженої багатовимірної траєкторії; для цього потрібен окремий планувальник.
7. **Навантаження на переривання:** у README є примітки про особливості MCPWM і RMT; уникати довгих блокувань і надмірного логування в критичному шляху.
8. **Апаратна зупинка:** програмна команда не замінює фізичний механізм безпечного відключення приводів.

### Що перевірити в коді та тестах

- `src/FastAccelStepper.h` — фактичні сигнатури API.
- `examples/UsageExample/UsageExample.ino` — мінімальний робочий сценарій.
- `examples/StepperDemo/` — команди та тестові послідовності.
- `tests/pc_based`, `tests/esp32_hw_based` — наявні тести.
- `CHANGELOG.md`, Issues — сумісність із обраним Arduino-ESP32.

**Висновок:** розглядати як пріоритетний драйвер **тільки якщо** лінійна платформа має сумісний STEP/DIR-драйвер. Інакше дослідити AccelStepper та офіційний урок Keyestudio 20.

## 6. Рекомендована логіка програми ARC

1. **Hardware layer:** окремі інтерфейси для сервоприводів, платформи, джойстика, кінцевих вимикачів.
2. **Manual mode:** мертва зона й фільтрація джойстика; плавне обмеження швидкості та кутів; керування клешнею.
3. **Coordinate map:** таблиця комірок `A/B/...` з каліброваними позиціями платформи й руки; одиниці вимірювання та нульова точка задокументовані.
4. **Semi-auto state machine:** `IDLE → MOVE_TO_PICK → LOWER → GRIP → LIFT_SAFE → TRANSPORT → LOWER_TO_PLACE → RELEASE → HOME → DONE`.
5. **Wrist leveling:** розрахунок кута зап'ястя за фактичною геометрією/орієнтацією суглобів; перевірити допустимі кути.
6. **Safety:** перевірка меж перед кожним рухом, тайм-аути, обробка недосяжних комірок, реакція на кінцеві вимикачі, аварійне зупинення.
7. **Diagnostics:** Serial 115200, стан автомата, ціль/поточна командна позиція, причина помилки; обмежити частоту повідомлень.

**Критичний принцип:** без датчика нуля/енкодера після перезапуску абсолютна позиція платформи може бути невідомою. Потрібне калібрування (homing) або надійна ручна процедура встановлення нуля. Підрахунок кроків сам по собі не вимірює реальне положення.

## 7. Дані, без яких не можна завершити робочу прошивку

- Точна модель ESP32 та версія Arduino-ESP32.
- Моделі й кількість сервоприводів, їхні безпечні діапазони та окреме живлення.
- Модель крокового двигуна і **фото/маркування драйвера** (ULN2003 чи STEP/DIR).
- Розпінування ESP32, схема загальної сигнальної землі та силового живлення.
- Довжина ходу платформи, передатне відношення, кроки/мм, кінцеві вимикачі.
- Геометрія руки: довжини ланок, осі обертання, висота захоплення, межі кутів.
- Тип джойстика/кнопок, схема вводу AB → CD.
- Маса вантажу, механічні обмеження, бажані швидкості.

## 8. План тестування перед захистом

1. Компіляція та завантаження мінімального прикладу на реальну плату.
2. Окремі тести кожного привода без навантаження, потім із навантаженням.
3. Вимірювання меж і встановлення нуля платформи.
4. Перевірка ручного керування, мертвої зони й плавної зупинки.
5. Перевірка безпечного положення руки та горизонту клешні.
6. Повторювані цикли AB → CD, облік невдалих захоплень і похибки позиціонування.
7. Перевірка відмов: перезапуск ESP32, відключення сигналу джойстика, недосяжна точка, кінцевий вимикач, аварійна зупинка.
8. Перевірка просідання напруги під навантаженням і відсутності перезавантажень.
